# Publication and Confidentiality Policy

This public repository is an independently authored reference study of general software engineering problems. Its source, examples, scenarios, and data must be synthetic and must make sense without a private deployment.

## Allowed

- General, independently documented techniques such as leases, fencing generations, source pinning, evidence reviews, staged decisions, and task graphs.
- Fresh implementation with fictional project names, traces, inputs, and examples.
- Public citations to preexisting external work and clear non-novelty statements.
- Explicitly labeled architectural proposals and independently reproduced results.

## Not allowed

- Copying or renaming private code, contracts, internal documentation, or directory trees.
- Publishing private issue IDs, commit histories, usernames, paths, hostnames, environment variables, architecture maps, credentials, logs, or production data.
- Claiming benchmark success, deployed capabilities, or operational authorization without accessible evidence.
- Relying on hidden private infrastructure to run a public example.

## Pre-publication review

Check repository content **and history**, comments, fixtures, metadata, CI logs, release artifacts, and generated output for confidential content. Follow automated scanning with a human semantic review; string filtering cannot detect architectural disclosure by inference. Verify copyright ownership and choose an appropriate license before inviting reuse.

This policy describes project publication hygiene; it does not establish that any particular past material has been declassified.
